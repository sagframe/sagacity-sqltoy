# sqltoy 5.6.jre8 缺陷修复升级计划（参照 Gitee 6.0 最新代码）

## Context

GitHub 仓库（`D:\personal\github\sagacity-sqltoy`，分支 `5.6.jre8`，版本 5.6.96.jre8，2026-09-20）是 JDK8 兼容维护线；Gitee 仓库（`D:\personal\gitee\sagacity-sqltoy`，分支 `6.0`，6.0.9/6.0.10，2026-11-11）是活跃开发线。两分支自 2020 年分叉、结构已不同（6.0 有 lambda 体系/JsonProvider/JDK17+ 依赖等），**无法 merge，只能逐 hunk 手工移植**。经逐项核查（25 项对照），6.0 在分叉后累积的约 20 项缺陷修复未进入 5.6.jre8，且 Gitee 5.6.jre8 还有 2 个 GitHub 侧遗漏的事务安全修复。

**目标**：将 6.0 中适用于 5.6 已有功能的缺陷修复回移到 GitHub 5.6.jre8，不引入新特性、不改变正常场景行为，保持 JDK8/httpclient4 兼容，升级版本至 5.6.97.jre8。

**用户已确认**：纳入 sqlite/TDengine 锁降级；不纳入新函数转换器（仅修已有转换器）；升版本+补 changelog；在当前 5.6.jre8 分支分批提交（不 push）。

## 每批次统一移植流程

1. `git diff 5.6.jre8 refs/remotes/gitee-6.0 -- <文件>` 逐 hunk 分类：**修复→移植**；新特性/新方言(highgo/g8)/jackson/httpclient5/lambda→跳过；纯重构（DialectFactory Phase 骨架化、ParallQuery 改名等）→跳过
2. 以 6.0 hunk 为蓝本手工适配 5.6 代码结构，jre8 语法兼容
3. 编译验证后 commit（中文提交信息，注明回移来源与内容）

## 验证

1. 每批次后：`JAVA_HOME=E:\jdk1.8 mvn -o clean compile`（core 模块）
2. 回归测试：临时把 core pom 中 surefire `<skip>true</skip>` 改 false（跑完恢复原样），`mvn -o test` 跑离线单测（BeanUtilTest 47 断言、SqlConfigParseUtilsTest、SqlWithAnalysisTest、FunctionUtilTest、MapperUtilsTest、SqlServerDialectTest、DialectUtilsTest、ReservedWordsUtilsTest 等；需要外部 DB 的测试会吞异常假绿，不影响）
3. 最终：四模块 `mvn -o clean install -Dmaven.test.skip=true`（对齐 mvn-install.bat 流程），确认 spring/solon 模块对 core API 兼容
4. `git log --oneline` + 逐批 `git show` 自查；汇总报告每批移植内容与验证结果
