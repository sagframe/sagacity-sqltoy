# sqltoy-orm-core 代码审查报告与修复计划

## 一、json/jsonb/vector/geometry 类型适配排查

写链路（setParamValue→JSONTypeUtil/setVectorValue/setGeometryValue）、读链路（buildColumnKinds→processResultRow→normalizeExtTypeValue / BeanUtil.convertType）、回写链路（resultUpdate→updateXXXValue）、DDL（DDLUtils.convertType）均已覆盖主流库，注释详实、多数经实库验证。发现的问题：

**P1（功能性缺陷）**
1. **VO 直映射路径缺扩展类型预处理**（SqlUtil.java:1318 reflectResultRowToVOClass）：直接 `rs.getObject(i+1)`，未复用 Map 路径的 TEXT_READ/EXT_BYTE 列预分类与 normalizeExtTypeValue。后果：①Oracle 21c 的 JSON/VECTOR 列 getObject 直接抛 ORA-17004/18722（ResultUtils:1342 注释已实锤），`find(sql, VO.class)` 整条查询失败；②sqlserver/mysql 系 byte[] 形态的 vector/geometry 不解码，String 属性经 BeanUtil:725 `new String(bytes)`（平台默认字符集）得到静默乱码。修复：processResultSet→reflectResultToVO 传入 dbType，按 ResultUtils.readColumnTypeNames+buildColumnKinds 预分类，TEXT_READ 列改 getString，取值后过 normalizeExtTypeValue（与 processResultRow 对齐）。
2. **SqlUtil.toGeometryBytes 硬引用 JTS**（SqlUtil.java:1077-1098）：`instanceof org.locationtech.jts.geom.Geometry` + `new WKBWriter(...)`。GeometryTypeUtil 头注释（2026-9-8）明确记载过同类问题：无 jts-core 环境类验证/执行期直接抛 NoClassDefFoundError，且此处 `catch(Exception)` 捕不到 Error。触发路径：mysql 系 updateSaveFetch 回写 geometry（WKT 字符串值，无需 JTS 即可到达）。修复：把 toGeometryBytes 整体下沉到 JtsGeometryCodec（如 `mysqlWktToInternalBytes`），SqlUtil 侧经 `GeometryTypeUtil.hasJts()` 门控转发；顺带将 BeanUtil:725 改为显式 UTF-8。
3. **DB2 12.1 内置空间引擎的版本分派未接线**：DialectExtUtils.isDB2BuiltInSpatial()（:798）已定义但全工程零调用；insert（DialectExtUtils:148）、update（DialectUtils:1239）、merge（DB2DialectUtils:71）三处都硬编码 `db2gse.ST_GeomFromText(?,0)`。而 :144-147 注释自证：12.1 起 db2gse schema 不复存在、内置函数第一参为 CLOB 需 cast。DB2 12.1 上三条链路全挂。修复：三处统一按 isDB2BuiltInSpatial() 分派 `ST_GeomFromText(cast(? as CLOB(1M)),0)` / `db2gse.ST_GeomFromText(?,0)`。

**P2**
4. OCEANBASE/TIDB 的 vector byte[] 解码缺口：buildColumnKinds（ResultUtils:1454）把 OB/TIDB 归入 mysqlLike→EXT_BYTE，但 normalizeExtTypeValue 的 VECTOR 解码分支（:1674-1680）只认 SQLSERVER/MYSQL/MYSQL57，OB/TiDB 的 byte[] 原样返回（geometry 分支却覆盖了 OB/TIDB，:1692-1695）。修复：vector 分支补齐或按 mysqlVectorBytesToText 统一处理。
5. h2 JSON 读回两条路径不对称：VO 路径经 JSONTypeUtil.unwrapJsonStringScalar 剥字符串标量外层引号，Map 路径（ResultUtils:1670）直接 `new String(bytes)` 不剥 → 同一列 find 成 Map 带引号、成 VO 不带。修复：Map 路径同样剥引号。
6. sqlserver 原生 json 列的 ResultSet 回写（JSONTypeUtil.updateJSONValue:156 走 updateString）没有 merge 路径那样的 convert(json,?) 定型门控，按 DialectUtils:913 的实测结论大概率报 "Implicit conversion json→nvarchar not allowed"（需实测确认）。
7. SRID 丢失：SQL 层包装 `ST_GeomFromText(?,0)` 硬编码 SRID=0（DialectExtUtils:142/148/151、DialectUtils:1237-1247 等），且 toGeometryString 对 JTS 对象输出纯 WKT（WKTWriter 不带 SRID）→ mysql 系/DM/DB2 落库 SRID 恒 0；仅 Oracle STRUCT 链路保留。建议：JTS→EWKT（"SRID=4326;POINT..."）输出并在包装函数中解析 SRID 参数，或文档明示该限制。

**P3**
8. 死代码：SqlUtil.ORACLE_VECTOR_TYPE（:185，反射探测后从未使用）；PostgreSqlDialectUtils 的 setJSONValue/updateJSON/setVectorValue/updateVector/setGeometryValue/updateGeometry 六个方法无调用者，且使该类硬 import org.postgresql.util.PGobject（与"按连接选同源驱动"的设计相悖）——建议删除。
9. OSCAR（神通）归类不一致：JSONTypeUtil.setNull 按 PG 系（OTHER），isPGFamily 却不含 OSCAR，DialectUtils:1276 又按 og 内核（cast(? as json)）。insert 裸?+setString 与 merge cast 路径绑定形态不一致，建议实测统一。
10. sqlite 时间双形态：参数绑定存毫秒 Long（setTimestamp），公共字段/DDL 默认值用 current_timestamp 文本（SqlUtil.getDBTime:2913-2941）→ 同列两种存储形态，比较/排序不可靠，建议统一（getDBTime 对 sqlite 返回毫秒表达式或绑定侧改文本）。
11. updateSaveFetch 回读覆盖实体（DefaultDialectUtils:620-622 BeanUtil.setProperty）时，geometry 列已是 WKT String、vector 列已是文本，写回 JTS Geometry/float[] 类型属性会失败或置脏。

## 二、跨库函数适配逻辑审查

框架设计良好：maskLiterals 线性掩码防字面量误替换、引号感知括号配对、参数递归转换、IGNORE=响亮失败。逐函数核对后发现：

**P1**
1. **DateDiff sqlite YEAR 分支括号不闭合**（DateDiff.java:241-242）：生成串 opens=6/closes=5（已逐字符核对；MONTH 分支是平衡的）→ `datediff('YEAR',d1,d2)` 在 sqlite 必然语法错误。修复：改为与 MONTH 分支同构 `"((CAST(...) - CAST(...)))"`。
2. **DateDiff DB2 MONTH 分支漏年份分量**（:182-184）：仅 `(MONTH(d2)-MONTH(d1))`，违反自身声明的"年月分量差"契约（其余 6 个库都是 `(YEAR差)*12+MONTH差`）→ 跨年结果错误（2024-01→2026-03 应 26，DB2 得 2）。修复：补 `((YEAR(d2)-YEAR(d1))*12+MONTH(d2)-MONTH(d1))`。

**P2**
3. DateDiff H2 WEEK 走原生 `DATEDIFF(WEEK,...)`（:169）：H2 按周边界计数，与契约"自然天差/7 截断"不一致（其他库 2026-9-5 已统一修正，H2 漏网）。修复：`DATEDIFF(DAY,...)/7`。
4. DateDiff sqlite 两参形态（:235-237）`round(epoch差/86400.0)`：列值含时间部分时与 mysql/oracle 的"去时间自然天差"契约偏差 ±1 天。修复：先 `date(...)` 截断再差。
5. ToChar 与 DateFormat 正则重叠（ToChar:15 同时匹配 date_format|FORMATDATETIME）：H2 目标下 `date_format(...)` 先被 DateFormat 转成 formatdatetime（正确产物），再被 ToChar 二次转成 to_char——最终形态依赖注册顺序，需验证 H2 2.x 是否支持 to_char；且两处 H2 分支都把 `%y`（两位年）映射成 `yyyy`（四位年），语义错误（DateFormat:86、ToChar:67）。修复：ToChar 正则去掉 date_format/FORMATDATETIME，%y→yy。
6. 分支覆盖缺口：Nvl/Concat/If 等未覆盖 CLICKHOUSE（nvl→ifNull、concat 多参）；Instr 假定 DB2 有 INSTR（Db2 LUW 通常只有 LOCATE/POSSTR，需确认）；Length 把 datalength（字节数）映射为 length/len（字符数），多字节库语义改变。
7. Concat oracle/db2/sqlite 分支将 `concat(a,b,c)` 转 `a||b||c`：mysql concat 任一参数 NULL 结果 NULL，oracle/db2 的 || 把 NULL 当空串、sqlite 传播 NULL——跨库语义差异未像 ConcatWs 那样文档化，建议注释明示或统一 coalesce 包裹。

**P3**
8. 函数正则统一用 `\W` 前缀，`_` 属于 \W → `base64_decode(`、`my_substr(` 等自定义函数会被误命中（Decode 有 args<3 兜底，但三参自定义 `xxx_decode(a,b,c)` 会被改写成 case when）。建议改 `(?<![.\w])` 负向后行断言。
9. FunctionUtils.functionNames 简写表缺 datediff/decode（默认注册列表有、简写映射没有，配置简写不生效）。
10. dialects() 用 contains 子串匹配："oracle" 匹配不上方言 "oracle11"（方向反了），自定义函数作者必须枚举全部变体，建议按逗号切分后精确匹配。
11. Trim 对 `trim('x' from col)`（省略 BOTH 关键字）形态：rest=arg.substring(4) 会截错（:60），最终 -1 回退 IGNORE 原样输出（目标库响亮报错，可接受但可修）。

## 三、整体缺陷与性能优化点

**P1/P2（性能热点）**
1. TenantFilterInterceptor.java:146：每次拦截（每查询）`Pattern.compile("(?i)\\Wwhere\\W")` 编译常量正则 → 提为 static final；且 `whereMatcher.find()` 返回值未检查，无 where 时 `start()` 抛 IllegalStateException。
2. ShardingUtils.java:447 matchReplace：分表替换发生在查询执行期，每次 `Pattern.compile(表名正则)` → 用 StringUtil 已有的带上限 Pattern 缓存（StringUtil:46-51）或按 sourceTable 缓存。
3. DateUtil：formatDate/parseString 每次调用 `new SimpleDateFormat(...)`（:821、:405、:644）与 `DateTimeFormatter.ofPattern(realDF)`（:397）——结果集逐行日期转字符串是高频路径 → 按 (format,locale) 缓存线程安全的 DateTimeFormatter，或 ThreadLocal<SimpleDateFormat>。

**P3**
4. SqlToyThreadDataHolder 各 clear 方法 `remove()` 后又 `set(null)`（:78-79、:98-99、:119-120 等）：set(null) 会重新插入 null 值 entry，remove 白做，池化线程残留 entry，TTL 场景还会传播 null 项 → 删掉 set(null)。
5. SqlUtil:2685 convertSqlMap `containsKey+get` 双查找 → 单次 get 判空。
6. 注释卫生：SqlUtil:714-729 两段 javadoc 叠放（getPGobjectByConn 的注释被 isPGFamily 截断）、:826 toVectorBytes 注释重复半句。

**正面确认（无需改动）**：insertSqlCache/convertSqlMap 有容量守卫；PG_GET_TYPE_METHODS 按类缓存反射 Method；DBProfile 以 URL 为 key 进程级缓存（含 PGobjectHolder、sqlserver json 探针）；processResultRow 列策略查询级预分类、行循环零字符串判定；PGobject 每参数新建防批量串值；maskLiterals 线性扫描无 ReDoS；资源释放统一走 preparedStatementProcess finally。整体看得出近期做过系统性性能与正确性治理。

## 修复实施计划（若批准）

**第一批（P1，建议立即修）**
- SqlUtil.reflectResultToVO 链路接入 dbType+buildColumnKinds+normalizeExtTypeValue（含 BeanUtil:725 UTF-8）
- toGeometryBytes 下沉 JtsGeometryCodec + hasJts() 门控
- DB2 三处 ST_GeomFromText 接 isDB2BuiltInSpatial() 分派（含 12.1 的 CLOB cast）
- DateDiff sqlite YEAR 括号、DB2 MONTH 年份分量

**第二批（P2）**
- OB/TIDB vector byte[] 解码、h2 json Map 路径剥引号、DateDiff H2 WEEK 与 sqlite 两参口径、ToChar/DateFormat 正则拆分与 %y 修正、TenantFilter/ShardingUtils/DateUtil 三处性能热点、CLICKHOUSE/DB2 函数分支补齐

**第三批（P3，可择机）**
- 死代码清理（ORACLE_VECTOR_TYPE、PostgreSqlDialectUtils 六个 PGobject 方法）、ThreadDataHolder set(null)、\W→(?<![.\w])、functionNames 补全、dialects() 精确匹配、SRID 保留方案、OSCAR/sqlserver-json 回写实测确认项

验证方式：每批修改后 `mvn -pl sqltoy-orm-core compile` + 运行现有单测；DateDiff/函数转换类可补字符串断言单测（括号平衡、各库输出快照）。
