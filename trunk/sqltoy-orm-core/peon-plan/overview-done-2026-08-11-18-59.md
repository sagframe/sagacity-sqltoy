# DateUtil.java Defect Fixes

## Context
`DateUtil.java` (`/sagacity-sqltoy/src/main/java/org/sagacity/sqltoy/utils/DateUtil.java`) has two confirmed bugs found during code review. A third suspected issue was reviewed and determined to be intentional (no change).

## Defects

### D1: WEEK_ENGLISH_NAME[3] typo "Thurday" → "Thursday"
- **Location**: line 74
- **Root cause**: Array literal misspells "Thursday" as "Thurday".
- **Impact**: `parseEnglishDate()` (line 1221-1223) loops over `WEEK_ENGLISH_NAME` and does `replaceFirst("(?i)" + WEEK_ENGLISH_NAME[i], WEEK_ENGLISH_NAKE[i])`. For index 3, the regex `"Thurday"` never matches a correctly-spelled `"Thursday"` in user input, so full "Thursday" dates slip through un-normalized. The line 1220 workaround `replaceFirst("(?i)Thur\\s", "Thu ")` only catches the abbreviation "Thur " (with trailing space), not the full word "Thursday".
- **Fix**: Change `"Thurday"` to `"Thursday"` in the array at line 74.
- **Regression test**: Add `testParseEnglishDateThursday()` to `DateUtilTest.java` — parse a date string containing "Thursday" and verify it parses correctly.

### D2: asSqlDate(LocalDate) returns java.util.Date instead of java.sql.Date
- **Location**: lines 1140-1145
- **Root cause**: Verbatim copy of `asDate(LocalDate)` (lines 1133-1138). Both return `Date.from(localDate.atStartOfDay().atZone(ZoneId.systemDefault()).toInstant())` which is `java.util.Date`.
- **Impact**: Method name promises `java.sql.Date` but returns `java.util.Date`. Currently dead code (no callers), but is a latent bug if ever used. Compare with `getSqlDate(Object)` (line 728) which correctly returns `java.sql.Date`.
- **Fix**: Change line 1144 to `return java.sql.Date.valueOf(localDate);`
- **No test needed** (dead code, but fix makes it correct for future use).

### D3: getWeekOfYear subtracts 1 — REVIEWED, NO CHANGE
- **Location**: line 919
- **Analysis**: `return targetDate.get(weekFields.weekOfYear()) - 1;` returns zero-based week-of-year. The comment at line 918 explicitly documents this: "获取周数（从1开始），减1转为从0开始" (gets week number from 1, subtract 1 to convert to 0-based). Only caller is `DateUtilTest.java:314` which just prints the result (no assertion). This is a deliberate design choice, not a bug. **No change.**
