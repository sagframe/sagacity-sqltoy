# sqltoy-orm 注释与提示信息规范

> 本规范适用于 sqltoy-orm 全部模块（sqltoy-orm-core、sqltoy-orm-spring、sqltoy-orm-spring-starter、sqltoy-orm-solon-plugin）的 Java 源码。
> 核心原则：**注释与 Javadoc 面向代码阅读者，使用中文；异常消息与日志消息面向运行时运维与国际化使用者，使用英文。**

## 1. 类头 Javadoc

统一使用项目自定义模板，位于 import 之后、类声明之前：

```java
/**
 * @project sagacity-sqltoy
 * @description 日期处理支持类，提供日常工作中的所有日期的操作处理
 * @author zhongxuchen
 * @version v1.0,Date:2008-12-14
 * @modify Date:2023-12-05 强化英文日期的解析以及localTime、localDateTime格式化
 */
```

规则：

| 字段 | 规则 |
|---|---|
| `@project` | 固定为 `sagacity-sqltoy` |
| `@description` | 一句话中文说明，说明类的职责，不写实现细节 |
| `@author` | 作者标识。同一人多标识统一为主标识 `zhongxuchen`；外部贡献者保留自己的标识（如 noear、夜の孤城） |
| `@version` | `v1.0,Date:YYYY-MM-DD`（创建日期，逗号后无空格，日期补零） |
| `@modify` | `@modify Date:YYYY-MM-DD 修改说明`。日期补零，不加花括号；历史记录只追加不删改 |

禁止：

- `package` 声明之前不允许出现任何 Javadoc 块（包括 IDE 生成的空 `/** */` 残留）。
- 不使用 `data:`（正确为 `Date:`）、`{Date:...,...}` 花括号等历史变体格式。
- 标签顺序固定：`@project` → `@description` → `@author` → `@version` → `@modify...`。

solon-plugin 中外部贡献者采用的标准结构（描述 + `@author` + `@since`）允许保留，但描述与标签不得挤在同一行。

## 2. 方法级 Javadoc

- 方法说明直接写在 Javadoc 首行，**不使用 `@todo`/`@TODO` 标签充当说明**（历史遗留标签已全量迁移）。真实的待办事项使用行内 `// TODO: 说明` 标注。
- 公共 API（`public`/`protected`）应有 Javadoc；`@param`、`@return` 每个标签必须带描述，不允许出现"有标签无描述"的空标签。
- 无新增成员方法时不需要补写全部历史方法，但改动某个方法时应同步完善其 Javadoc。
- 泛型/参数中的 HTML 敏感字符注意转义；不使用未闭合的标签。

```java
/**
 * 保存单条记录对象，主键为空时自动产生主键值
 *
 * @param entity   待保存的实体对象
 * @return 保存后的实体对象（包含数据库生成的主键）
 */
Object save(Object entity);
```

## 3. 行内注释

- 使用中文，解释**为什么**这样做（约束、坑、规范依据），而不是复述代码做了什么。
- 修改标记（`// add 2022-2-10 xxx`、`// update 2020-09-07 xxx`）不再新增；历史的保留。新改动如需说明直接写说明本身，日期信息由 git 历史承载。
- **禁止提交注释掉的代码**。不用的代码直接删除，需要时从版本历史找回。
- 真实待办统一格式：`// TODO: 说明`；不使用 FIXME。
- 测试类中允许使用分节注释：`// ==================== 被测类：场景 ====================`。

## 4. 异常消息（英文）

格式：`动作/场景 + 具体原因 + 怎么办`，示例：

```java
throw new IllegalArgumentException("findOneById expect single record, but found [" + result.size()
        + "] rows, please check the query conditions!");
```

规则：

- 语言：英文，句首大写，结尾不加句号；提示性结尾用 `please check/check ...!` 风格。
- 多个动态值用 `[]` 包裹，便于日志检索。
- 拼接方式：字符串 `+` 拼接（异常消息不经过日志框架，不使用 `{}` 占位符）。
- 常用句式对照：
  - 参数为空：`xxx is null, please check!` / `xxx can not be null!`
  - 类型不支持：`xxx type is not supported!`
  - 数量不符：`expect [n] but found [m]`
- 提示必须可行动：告知用户检查哪个配置/参数，而不是只抛出内部状态。

## 5. 日志（英文）

- 语言：英文；一律通过 SLF4J logger 输出。
- **占位符：一律使用 `{}`**，禁止 `+` 拼接（`logger.debug("Root path: {}", rootPath)`）。
- 级别语义：
  - `warn`：配置问题或可自动恢复的异常（不中断运行）；
  - `error`：伴随异常抛出或功能失败的场景，异常对象作为最后一个参数传入；
  - `debug`：诊断信息（解析过程、扫描路径等）；
  - `info`：仅用于启动阶段的关键过程提示。
- **禁止** `System.out` / `System.err` / `e.printStackTrace()`，统一改用 logger；异常对象用 `logger.error(msg, e)` 输出而非拼接 `e.toString()`。
- 消息中不要手工换行（`\n` 前后缀）。

## 6. 测试代码

- 断言异常消息时使用与实现一致的英文关键词（消息英文化后同步更新断言），断言片段取消息中稳定的部分（如字段名、数量），不整串比对。
- 测试自身的注释遵循第 3 节；测试类应有类级 Javadoc 说明覆盖场景。

## 7. 历史遗留处理约定

- 历史注释中的日期标记、旧格式仅在新触碰该文件时顺带修正，不做专项考古式重写。
- 修改历史（`@modify`）只追加；不删除他人（含外部贡献者）的署名与说明。
